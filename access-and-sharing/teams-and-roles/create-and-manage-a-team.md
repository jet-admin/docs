# Create and manage a team

Create a named team to organize users with shared permissions or properties.

## Create a team

1. Open **Users** in the builder navigation.
2. Select the **Teams** tab.
3. Select **Add Team**.
4. Enter a **Team Name**, such as Customer Support.
5. Select **Create**.
6. Review the resulting team's settings before assigning users.

The creation dialog describes teams as a way to group users, grant permissions, and assign properties. Creating a named team does not by itself document which actions that team should be allowed to perform.

## Assign people and properties

Select the intended team when [inviting a user](../members-users-and-groups/invite-by-email.md) or [creating an invitation link](../members-users-and-groups/invite-with-a-link.md). Review existing membership before changing assignments.

Use **Add Property** on the Teams tab when the group needs a shared attribute. Keep the meaning and type consistent with the [user and team property design](../members-users-and-groups/user-and-team-properties.md).

## Review team permissions

Document expected access to the builder, settings, membership management, pages, and data actions. Use the controls available for your app version, then verify the result with [representative test accounts](../overview/test-access.md).

### Classic builder reference

Older team screens group permissions into Project Permissions and Page Permissions. Their page choices include Full Access, Read-only, Custom Access, and No Access. These labels describe the Classic interface and may differ from your current builder.

For Classic conditional data actions, see [conditional add, edit, and delete](../../classic-app-builder/design-and-structure/components-visibility/conditional-add-edit-and-delete.md).
