# Pages and components

Applies to **Classic App Builder**. Screens and recordings in this section show the Classic interface.

Build an interface from pages, layouts, and components, then connect it to data and actions.

## Choose a reference

* [Customize pages](pages/) for page structure and navigation.
* [Components](components/) for the component reference.
* [Generate a record page or dashboard](../classic-tutorials/ui-in-seconds.md) for an initial interface.
* [Field values](column-values/) for displayed values.
* [Nested filters](nested-filters.md) and [Advanced filters](advanced-filters.md) for data selection.
* [Sort](sort.md) and [Group](group.md) for presentation.
* [Dropdown popups](dropdown-popups.md) for additional controls.

## Change an existing page

1. Identify the component and the resource it uses.
2. Review its displayed fields, filters, and selected-record behavior.
3. Adjust the relevant settings.
4. Test with a populated result, an empty result, and a different selection.
5. Check the page with the intended user role before publishing.

Continue with [Data binding and variables](../binding-and-values/) when the component needs another component's value.

## Visibility and authorization

[Visibility rules](visibility-rules.md) and [Conditionals](components-visibility/) control presentation. Hiding a component does not by itself establish that its underlying data request is forbidden. Use [App and data permissions](../../access-and-sharing/app-and-data-permissions/) to review enforcement.
