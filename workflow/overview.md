# Workflows overview

Use a workflow when a business process follows defined steps. Choose the event that starts it, add actions and conditions, then test each path before letting it change live data.

Start with [Triggers](triggers-steps-and-parameters/triggers.md), [Steps](triggers-steps-and-parameters/steps/), and [Inputs, Outputs, Parameters](triggers-steps-and-parameters/inputs-outputs-parameters.md). You can also [generate workflows with AI](approvals-and-workflows-with-ai/workflows-with-ai.md). Review generated actions, credentials, and write operations before running them.

Other common patterns include [Scheduled Workflows](schedules-and-webhooks/scheduled-workflows.md), [Webhooks](schedules-and-webhooks/webhooks.md), and [Approval Workflow](approvals-and-workflows-with-ai/task-approval.md). Use [Test & Debug](test-debug-and-inspect-runs/test-and-debug.md) before publishing.
